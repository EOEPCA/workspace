    Configure Workspace⚓︎

    Follow the component guides for installation. The EOEPCA+ deployment links below use a fixed revision with the configuration examples.

    Components⚓︎

    Component and installation guide Purpose Documented version requirement
    Kubernetes Runs controllers and workloads. Needs NetworkPolicy enforcement and persistent volumes. No Workspace minimum stated. Educates 3.8 bundles clients for 1.33–1.36.
    Ingress controller (APISIX) Routes sessions; needs WebSockets, wildcard DNS, and TLS. No minimum stated; see the runtime requirements.
    Gateway API controller (Envoy Gateway) Routes Data when using HTTPRoute; see the deployment. HTTPRoute with cross-namespace routes; header regular expressions for S3. External PostgreSQL needs TLSRoute v1.
    Crossplane Reconciles Storage and Datalab resources. >= 2.0, < 3.0.
    Keycloak Manages workspace identities, groups, roles, and OAuth clients. 26.2 or later for standard token exchange; no provisioning minimum stated.
    Educates Provides browser sessions, terminals, and editors. The notebooks use workspace vClusters instead. Pinned to 3.8.0; no minimum stated.
    Kyverno Enforces the selected Educates security policies. Bundled policies require 1.11.0 or later. Extra platform policies can require newer versions.
    S3-compatible object storage Stores workspace data. Backend supported by Provider Storage; no common minimum stated.
    Provider Storage Creates buckets, storage identities, grants, and credential Secrets. >= 0.4.0 for the current Workspace API.
    Provider Datalab Creates membership, Data services, workspace vClusters, browser sessions, and managed services. Documented API requirement: >= 0.12.0. This demo was checked with 0.12.0-rc.8.
    rm-workspace-api Optional Workspace management UI, HTTP API, and token exchange. No minimum stated; see the deployment’s image tag.
    Managed-store operators Optional PostgreSQL, MongoDB, and Redis services. See the provider guide’s tested operator pins for enabled stores.
    CNCF Distribution The registration notebook deploys its OCI registry inside the workspace vCluster. No minimum stated. The example manifest pins 3.1.2 by digest.

    Install provider and function dependencies, namespaced ProviderConfigs, and RBAC through the provider guides. Pins and tested versions do not establish minimum versions.

    Without rm-workspace-api, create Storage and Datalab resources through Kubernetes or GitOps. You then have no Workspace management UI, Workspace HTTP API, or Workspace token-exchange endpoint. The notebook quickstart needs the API.

    1. Set the environment⚓︎

    Adapt the deployment’s pipeline values: IAM URLs and realm, storage endpoint, ingress domain and certificate, Gateway listeners, and Pod and Service network ranges. For browser sessions, keep the Educates ingress values consistent. The provider guide lists fields and defaults.

    The workspace-pipeline chart installs the configuration packages and creates the EnvironmentConfig. It copies environmentconfig into EnvironmentConfig.data, except for name and annotations. The example’s prerelease package overrides differ from the chart defaults. Keep exact pins in your deployment.

    The example uses the EnvironmentConfig name datalab. Select it on each resource with an annotation or label:

    Resource Key Value
    Storage storages.pkg.internal/environment datalab
    Datalab datalabs.pkg.internal/environment datalab

    For resources created by Workspace API, set PROVIDER_ENVIRONMENT=datalab.

    2. Create a workspace⚓︎

    With Workspace API, configure its deployment and accounts and roles, then run Workspace Management. It creates a workspace and waits for storage, Data, the virtual cluster, and the managed registry.

    For direct Kubernetes use, save the provider’s Storage example as storage.yaml and Datalab example as datalab.yaml. Adapt them before applying:

    1. Use ws-example for both resource names and the Storage principal, in namespace workspace. Choose a unique bucket name. Remove sample bucket access requests and grants.
    2. Set both environment selectors from the table above. Select the storage backend with spec.crossplane.compositionSelector.matchLabels.provider, for example minio.
    3. Set the EnvironmentConfig’s storage.secretNamespace to workspace. Storage creates a Secret named after its principal; Datalab reads it using its resource name.
    4. Set an existing Keycloak username in spec.users. For the STAC notebooks, use the spec.vclusters configuration from the workspace example. Omit spec.sessions unless you need browser sessions.
    kubectl apply -n workspace -f storage.yaml
kubectl wait -n workspace --for=condition=Ready storage/ws-example --timeout=300s
kubectl apply -n workspace -f datalab.yaml
kubectl wait -n workspace --for=condition=Ready datalab/ws-example --timeout=300s
kubectl get storages,datalabs -n workspace

    3. Use the workspace⚓︎

    With Workspace API, continue with the quickstart. The notebook guide lists services needed for each example. For direct Kubernetes use, check Datalab status for service and session addresses.
